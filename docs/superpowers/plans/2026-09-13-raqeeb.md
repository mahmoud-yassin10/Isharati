# Raqeeb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Raqeeb as a teacher + student web app that teaches Egyptian curriculum through ESL and a real interactive Physics simulation, then grow PDF→lesson generation on that same lesson format.

**Architecture:** Keep FastAPI as the ESL + (new) lesson/auth API. Next.js is the only UI. Simulations run in the browser from a typed `SimulationKind` registry. LLM planning is server-side and can only fill the lesson JSON — it cannot emit simulation code.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind, Arabic RTL, Matter.js (or a 1D integrator) for motion, FastAPI, SQLite + SQLAlchemy, existing HF-SMCA / pose pipeline, OpenRouter for later PDF planning.

**Spec:** [docs/raqeeb-spec.md](../../raqeeb-spec.md)

## Global Constraints

- Product name in UI copy is **Raqeeb**, not Isharati.
- Arabic RTL for all product UI.
- Do not load `best_model.pt` in the browser.
- Simulations must implement official formulas in our code (`a = F / m` for v1).
- LLM must not generate simulation source in v1–v2.
- Physics glossary terms not in the 502-class lexicon use `esl_mode: "fingerspell"` or `"none"`.
- CORS already allows `http://localhost:3000`.
- Run API from `backend/` on port 8000; web on 3000.
- After code file changes, run `graphify update .`.

### Task 4: Newton 2nd interactive simulation

**Files:**
- Create: `frontend/src/features/simulations/types.ts`
- Create: `frontend/src/features/simulations/registry.ts`
- Create: `frontend/src/features/simulations/newton-2nd.tsx`
- Create: `frontend/src/features/simulations/newton-2nd.test.ts` (formula unit tests)

**Interfaces:**
- Consumes: `LessonStep.simulation`
- Produces:

```ts
export type SimState = { F: number; m: number; a: number; x: number; v: number };

export function newtonAccel(F: number, m: number): number {
  if (m <= 0) return 0;
  return F / m;
}

export function SimulationView(props: {
  kind: "newton_2nd";
  params: Record<string, number>;
  goal?: { key: string; value: number; tolerance: number };
  onState?: (s: SimState) => void;
  onGoalMet?: () => void;
}): JSX.Element;
```

Must include: F slider, m slider, live `a`, moving box, reset, F–a graph, challenge banner when `goal` is set.

- [ ] **Step 1: Unit test `newtonAccel(10, 5) === 2` and `newtonAccel(10, 0) === 0`**

- [ ] **Step 2: Build the lab UI; motion uses `a` from `newtonAccel`, not Matter.js gravity**

Integrate time with `requestAnimationFrame`: `v += a * dt; x += v * dt`. Clamp world bounds and bounce or wrap — pick clamp + reset.

- [ ] **Step 3: Goal: when `|a - goal.value| <= tolerance`, call `onGoalMet` once**

- [ ] **Step 4: Isolated page `/dev/newton` for manual QA (remove before production polish)**

- [ ] **Step 5: Commit**
